# 已知限制与覆盖范围

## 一、系统覆盖

| 系统 | 构建号 | 状态 | 依据 |
| --- | --- | --- | --- |
| macOS 26.7.1 | 25G241 | **已实测** | 硬件验证 |
| macOS 26.7.2 | 25G332 | 允许 | 内核调试包离线核对（IOSkywalkFamily 同、IO80211Family AWDL 代码逐指令一致） |
| macOS 26.7.3 | 25G342 | 允许 | 同上 |
| macOS 15.8 | 24H23 | 允许 | 内核调试包离线核对 |
| macOS 15.8.3 | 24H241 | 允许 | 同上 |
| macOS 15.8.1 / 15.8.2 及其他 15.8.x | 24H32 / 24H232 / … | **expected** | 同内核训练线，虚表校验仍需通过；属"预期可用"，未逐个验证 |
| macOS 14.8.9 | 23J631 | 允许 | 内核调试包离线核对 |
| 其他任何构建 | — | **被挡住** | 驱动退化为普通 AirportItlwm，Wi-Fi 正常，AWDL 不启动 |

表里的判断写在 `include/AWDLBuildGuard.hpp`。新增一个系统版本＝补一条白名单 + 按该版本的内核调试包核对虚表槽位，不是改个版本号就行。

## 二、硬件

- 只在 **AX200** 上做过完整实测（双向传输、并发、长时间）。
- AX210 / AX211 / AX201 一类同族网卡按上游硬件表适配，但 AWDL 侧未逐一验证。
- 仅 **x86_64**。Apple Silicon 不适用。
- 需要网卡能做 5 GHz 信道切换与多 station 上下文；只支持 2.4 GHz 的卡无法承载 AWDL。

## 三、明确不支持

| 项 | 说明 |
| --- | --- |
| WPA3-only 网络 | 需要 SAE 完整实现，本仓库沿用上游限制 |
| 强制 PMF | 同上 |
| MLO（Wi-Fi 7 多链路） | 未实现 |
| IPv4 载荷 | AWDL 数据面按 IPv6 封装，MTU 1500，不支持 jumbogram |
| 三个以上并发对端 | 代码支持，但只验证到 3 台手机 |
| 蓝牙 | 不在本仓库内 |

## 四、性能边界

| 场景 | 实测 |
| --- | --- |
| 未连 Wi-Fi，手机 → Mac | 约 17 MB/s，重传 0 |
| 未连 Wi-Fi，Mac → 手机 | 约 29 MB/s（935 MB / 32 秒），重传 0 |
| 已连 Wi-Fi | 可用，吞吐明显低于未关联态（射频要分给 station） |

三个结构性上限：

1. **时隙对齐偏粗**：一轮 16 个 legacy 时隙，靠单帧堆速率，没有做更细的窗口聚合，因此达不到 Apple 原生卡的水平。
2. **20 秒扫描硬上限**：长传输期间每 20 秒左右放行一次扫描，表现为极短速率抖动。这是为了避免扫描面板空白做的取舍。
3. **单射频**：AWDL 与 Wi-Fi 共用一颗射频，二者同时吃满时只能降级。

## 五、蓝牙侧（不在本仓库）

AirDrop 的发现阶段依赖蓝牙 LE。当前 Intel 蓝牙的已知缺口：

- 控制器没有 resolving list（`0x2027` 未下发），空口用 RPA，出向 LE 建连 6 秒后返回 `status=702`。
- 影响：iPhone 热点凭据传递、部分接力配对。
- 不影响：入向连接、广播、已配对设备的常规使用。

蓝牙侧至少需要 `BlueToolFixup` + `IntelBluetoothFirmware`，加载顺序 `Lilu` → `IntelBluetoothFirmware` → `BlueToolFixup`。

## 六、风险

AWDL 层直接子类化 Apple 私有类，按虚表槽位调用。校验只覆盖"表布局"，不覆盖"函数行为"。因此：

- 系统小版本升级后，即使虚表没变，也可能出现未预期的行为差异。
- 用 `-itlawdlanybuild` 绕开白名单，**可能导致内核崩溃**，且崩溃发生在网络栈内部，难以定位。
- 出问题时的第一动作是关掉 kext（`Enabled = false`）重启，不要反复试。
